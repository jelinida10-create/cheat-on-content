# /cheat-group-research — 赛道竞争格局分析

每个内容创作者的第一道题不是"怎么做"，而是"做什么赛道 + 在这个赛道里站哪个位置"。

`/cheat-learn-from` 假设你已经选好了对标——这个 skill 是**更早的动作**：在你选对标账号之前，先扫一遍整个赛道，知道谁在做什么、哪里拥挤、哪里还有机会。

**与 `/cheat-learn-from` 的区别**：

| | `/cheat-group-research` | `/cheat-learn-from` |
|---|---|---|
| 范围 | 3-8 个账号，每个 3 条样本 | 1 个账号，5-15 条样本 |
| 目的 | 绘格局、找白空、选 benchmark | 深挖 pattern、派生 rubric 信号 |
| 输出 | `group_research/<赛道名>.md` + 候选机会 | `benchmark.md` + `script_patterns.md` + `rubric_notes.md` |
| 做法 | 横向广扫 | 纵向深挖 |
| 时机 | 选对标**之前** | 选好对标**之后** |

典型路径：`/cheat-group-research` → 确定赛道定位 + 选出最佳 benchmark → `/cheat-learn-from` 深挖那个 benchmark

## Overview

```
[用户：研究这个赛道 / group research]
  ↓
[Phase 0: 检查状态 + 加载 context]
  ↓
[Phase 1: 定义赛道 + 收集账号名单（3-8 个）]
  ↓
[Phase 2: 每个账号收集轻量数据（top 3 视频 + 粉丝量 + 调性）]
  ↓
[Phase 3: Claude 绘制竞争格局地图]
  ↓
[Phase 4: 白空分析（拥挤区 vs 稀疏区 vs 无人区）]
  ↓
[Phase 5: 推荐最佳 benchmark 账号 + 你的定位建议]
  ↓
[Phase 6: 用户 review → 改 → 落盘 group_research/<赛道名>.md]
  ↓
[Phase 7: （可选）注入白空机会到 candidates.md]
  ↓
[Phase 8: 推荐下一步行动]
```

## Constants

- **MIN_ACCOUNTS = 3** — 少于 3 个账号绘不出格局，拒绝继续
- **MAX_ACCOUNTS = 8** — 超过 8 个合成质量下降，建议用户缩窄赛道范围
- **SAMPLES_PER_ACCOUNT = 3** — 每个账号只要 3 条（格局扫描，不是深挖）
- **REQUIRED_PER_SAMPLE = ["title", "plays"]** — 最低要求（只需标题 + 播放量，其他选填）

## Inputs

| 必填 | 来源 |
|---|---|
| `<赛道名>` | 用户参数；缺失则询问 |
| 账号名单（3-8 个） | 用户提供 |
| 每账号 top 3 视频：标题 + 播放量 | 用户提供 |
| `.cheat-state.json` | 读 benchmark_status / calibration_samples |

| 可选 | 来源 |
|---|---|
| 粉丝量 | 用户提供（更精准的格局判断） |
| 调性描述（用户印象） | 用户提供 |
| 点赞 / 评论数 | 用户提供（有则更好） |

## Workflow

### Phase 0: 检查状态 + 加载 context

1. 读 `.cheat-state.json`：
   - 不存在 → **不**强制要求 init（group research 可以在 init 之前跑，用来决定进不进这个赛道）
   - 存在 → 读 `benchmark_status` 和 `benchmark_name`
2. 检查 `group_research/` 目录是否存在 + 有没有已有的赛道报告：
   - 有 → Phase 1 里提醒用户"你已经研究过 N 个赛道"

### Phase 1: 定义赛道 + 收集账号名单

#### 参数解析

- 用户提供了 `<赛道名>` 参数 → 直接用
- 用户提供了 `— accounts: 账号1,账号2,...` → 直接用（跳过询问）
- 否则 → 询问：

```
你想研究哪个赛道？

给我：
1. **赛道名字**（1 句话描述，比如"知识科普 / 情感博主 / AI 创业 / 职场吐槽"）
2. **3-8 个你想分析的账号**（账号名 + 平台，不需要 URL）

> 小提示：先想"你自己打算做什么内容"——这样选来的账号才是真实的参考系。
> 不知道有哪些账号？先给我赛道名，我帮你思考哪些维度值得看。
```

如果用户只给了赛道名没给账号 → 询问：

```
好，[赛道名]。这个赛道里你知道哪些账号？

格式随意，一行一个就行：
  账号A（抖音）
  账号B（B站）
  ...

3 个够了，最多 8 个（多了我没法深挖，帮你选最有代表性的）。
```

收到账号名单后，校验数量：
- `< MIN_ACCOUNTS (3)` → 拒绝：

```
❌ 少于 3 个账号绘不出格局。

原因：两个账号我只能说"A 做这个，B 做那个"——这是对比，不是格局分析。
3 个以上才能看出"这个赛道的主流路子" vs "另类路子"。

你还知道这个赛道里的其他账号吗？或者告诉我你的赛道，我帮你想。
```

- `> MAX_ACCOUNTS (8)` → 建议缩窄：

```
⚠️ 你给了 N 个账号，分析质量会下降（我对每个账号只能看 3 条视频）。

建议：
a) 只保留你最想了解的 8 个
b) 缩窄赛道范围（比如"职场吐槽"→"刚毕业职场博主"），更聚焦

或者你直接说"全部 N 个"，我就全分析，但结论粒度会粗。
```

### Phase 2: 每个账号收集轻量数据

**核心理念**：这是广度扫描，不是深挖。每个账号只要 top 3 视频 + 粗粉丝量就够绘格局。

逐账号询问（一次一个，避免用户信息过载）：

```
好，我们一个一个来。先说 [账号A]：

1. 这个账号的**粉丝量级**（不用精确，量级就行：1w以下 / 1-10w / 10-100w / 100w+）

2. 他们的 **top 3 视频**（播放量最高的 3 条，或你觉得最有代表性的 3 条）：
   - 标题 + 播放量（其他数据有的话给——点赞/评论）

3. 你的**印象**：这个账号整体在做什么风格/方向？一句话就好。

格式随意，我能解析就行。
```

**简化模式**（用户嫌麻烦）：如果用户说"我只能给标题"或"我懒得给数据"→ 接受纯标题版：

```
好，只有标题也行。给我 [账号A] 的 3 个代表视频标题。
（没有数据的情况下，格局分析会更定性——你需要自己判断每个账号的体量差别。）
```

收集完所有账号后 → Phase 3。

**边收集边记录**：对每个账号，在内存里维护：

```
账号名: <name>
平台: <platform>
粉丝量级: <tier>  # small(<1w) / mid(1-10w) / large(10-100w) / mega(100w+) / unknown
样本: [
  {title: ..., plays: ..., likes: ..., comments: ..., impression: ...},
  ...
]
用户印象: <一句话>
```

### Phase 3: 绘制竞争格局地图

读取所有账号数据 → 分析：

#### 3a. 内容类型分布

把每个账号的内容归类到 2-4 个维度（根据赛道特点选维度）：

常见维度组合（按赛道类型）：

| 赛道 | 常用维度 |
|---|---|
| 知识 / 科普 | 「深度 vs 速食」+ 「学术感 vs 趣味感」|
| 情感 / 生活 | 「个人叙事 vs 普遍议题」+ 「共鸣驱动 vs 建议驱动」|
| 职场 / 商业 | 「经验输出 vs 批判视角」+ 「实用干货 vs 叙事故事」|
| 娱乐 / 时评 | 「热点跟风 vs 原创议题」+ 「情绪输出 vs 分析框架」|

把每个账号落在这个 2D 格局里（文字版，不是真正的图）：

```
格局地图（[维度X] × [维度Y]）：

           深度内容
               │
  学术感 ──────┼────── 趣味感
               │
         速食内容

账号分布：
- 账号A（10w粉）：[深度 × 学术感]——详细研究型，每条 15 分钟
- 账号B（50w粉）：[速食 × 趣味感]——3 分钟金句型
- 账号C（5w粉）：[深度 × 趣味感]——深度但说人话，尝试差异化
- ...

最拥挤的区域：[速食 × 趣味感]（4/7 账号在这里）
最稀疏的区域：[速食 × 学术感]（0 个账号——没人做）
```

#### 3b. 表现分析

按账号体量分层，看什么做法在哪个量级有效：

- 大账号（100w+）在做什么 → 赛道主流打法
- 中量级（10-100w）最近在做什么新尝试 → 可能的新方向
- 小账号（<10w）里有没有某类内容特别跑量 → 被大账号低估的机会

#### 3c. 内容模式总结

看所有账号的 top 3 标题，提炼：
- 哪些内容类型普遍高播放（跨账号的共识）
- 哪些是某账号的独家优势（只有他能做）
- 哪些是机械重复（大家都做但都差不多）

### Phase 4: 白空分析

白空 = 这个赛道**有需求但供给不足**的内容细分。

三类白空：

**A. 格局白空**（内容形态没人占）：
- 格局地图里稀疏的象限
- 例："这个赛道每个人都做'干货清单'，没人做'失败案例深挖'"

**B. 表现白空**（偶发高播放但无人持续做）：
- 某个赛道内几个账号都偶然发过的某类内容，表现远超平均，但没人持续深耕
- 例："3 个账号里各有 1 条'揭秘内幕型'视频是最高播放，但他们主账号不走这路"

**C. 受众白空**（某类受众没被服务好）：
- 基于内容调性判断的推断（不是数据，是逻辑推断）
- 例："这个赛道所有内容都在说给'想转行的人'听，没有说给'想在现在的行业做好'的人听"

每类白空给 1-2 个候选机会，附：
- 机会描述（一句话）
- 为什么这是白空（证据）
- 风险（为什么没人做可能有原因）

### Phase 5: 推荐最佳 benchmark 账号

根据分析结果，给用户：

**5a. 推荐逻辑**

```
基于你的赛道分析，我推荐你用 [账号X] 作为 benchmark。

原因：
- 体量：[粉丝量级]——有一定规模但不是头部（头部太难学，学个调性在你量级还行的）
- 定位：[账号X 的格局位置]——和你打算做的 [你的目标定位] 最接近
- 样本质量：他的 top 视频 [有/没有] 明显高低分化，适合拆 pattern

备选：
- [账号Y]（理由）
- [账号Z]（理由）
```

**5b. 你的定位建议**（根据白空分析）

```
基于格局分析，我建议你试试这个定位：

[一句话定位描述]

具体说：
- 避开：[最拥挤的区域]（已经有 N 个账号在做）
- 进入：[你推荐的白空]（供给不足，且有表现证据）
- 初始可以学：[benchmark 账号] 的 [某几个具体维度]
```

**注意**：如果用户已有 benchmark（`benchmark_status=imported`），对比说明：
- 如果原有 benchmark 仍是最佳选择 → "你现在的 benchmark [名] 仍然最适合，不需要换"
- 如果发现更好的 → "发现了比 [原 benchmark] 更合适的——[新账号X]，建议跑 `/cheat-learn-from --replace [X]`"

### Phase 6: 用户 review → 落盘

展示完整报告 → 询问：

```
我从你给的 N 个账号绘出了：

📊 格局地图：[最拥挤的区域] vs [最稀疏的区域]
⬜ 白空机会：[数量] 个
🎯 推荐 benchmark：[账号名]（[一句理由]）
📍 建议定位：[一句话]

回 "ok" 我落盘，
或告诉我哪里判断有问题。
```

### Phase 7: （可选）注入白空机会到 candidates.md

如果用户传了 `— inject-candidates` 参数，或主动说"加进候选池"：

1. 对每个白空机会，生成 candidate entry（按 [candidate-schema.md](../../shared-references/candidate-schema.md) 格式）
2. 标注来源 `source: group_research` + `read_status: skim`（还没深挖，只是线索）
3. 追加到 `candidates.md`

如果用户没说 `— inject-candidates`，Phase 8 里主动询问：

```
要把这些白空机会加进 candidates.md 吗？（之后 /cheat-seed 或 /cheat-recommend 时会读到）

a) 加全部 N 个
b) 我挑一下再加
c) 不加，先看着
```

### Phase 8: 推荐下一步行动

```
✅ 赛道分析完成：group_research/[赛道名].md

下一步建议：

1. **选 benchmark 深挖**（最重要）：
   `/cheat-learn-from [推荐的benchmark账号名]`
   → 导入 5-10 条他们的样本，派生你自己的 rubric 信号

2. **把白空机会加进候选池**（如还没加）：
   `/cheat-group-research — inject-candidates`
   → 然后 `/cheat-seed` 或 `/cheat-recommend` 时就能看到这些机会

3. **先 init 再开始**（如果还没 init）：
   `/cheat-init`

[如果用户已有 benchmark]
你现在有 benchmark [名]。根据这次分析：
- 原 benchmark 仍适合 → 不用换，直接 `/cheat-learn-from --append` 补更多样本
- 建议换 → `/cheat-learn-from --replace [新账号]`
```

## Key Rules

1. **广度优先，不是深度**——每账号只要 3 条样本。用户想深挖某个账号，让他用 `/cheat-learn-from`
2. **MIN_ACCOUNTS = 3**，少于 3 个拒绝（绘不出格局）
3. **白空必须有证据**——不能凭感觉说"这里有白空"，要指向具体的账号数据或表现差异
4. **定位建议不强迫**——Claude 提供方向，不替用户拍板"你就应该做这个"
5. **可在 init 之前跑**——用户可能先做赛道研究再决定要不要做这个赛道，不强制检查 `.cheat-state.json`
6. **有 benchmark 时要对比**——如果用户已有对标账号，对比说明"换 vs 不换"
7. **候选池注入默认询问**——不自动写 `candidates.md`，先问用户

## Refusals

- 「我只有 1-2 个账号，帮我分析」 → 拒绝。最少 3 个，否则不是格局分析是账号对比。建议补充到 3 个
- 「帮我下载对标视频」 → 拒绝。引导用户自己用 yt-dlp / 轻抖等工具提取
- 「直接告诉我该做哪个赛道」 → 拒绝。这个 skill 的价值是**给你信息让你做判断**，不是替你拍板。Claude 不知道你的时间 / 资源 / 兴趣约束
- 「跳过账号数据，凭你的知识帮我分析这个赛道」 → 拒绝。知识截止 + 平台动态快，Claude 的训练数据不代表现在的赛道状态。必须用用户提供的真实数据
- 「一次给我分析 15 个账号」 → 拒绝或建议拆分（超过 8 个合成质量下降，建议分两次 / 缩窄赛道范围）

## Integration

- 上游：`/cheat-init` Phase 2.5 在 `benchmark_status=none` 时可以先建议跑 `/cheat-group-research` 再决定 benchmark
- 上游：`/cheat-status` 在 `benchmark_status=none + calibration_samples=0` 时可提示"还没选 benchmark？跑 `/cheat-group-research` 先看清赛道"
- 下游：`/cheat-learn-from` 的 `<账号名>` 参数，通常来自这里的推荐
- 下游：`candidates.md`（通过 `— inject-candidates` 注入白空机会）
- 下游：`group_research/<赛道名>.md`（持久化竞争格局，方便之后回顾）

## group_research/ 文件的生命周期

- **首次建立**：Phase 6 落盘
- **更新**：再次跑 `/cheat-group-research <同赛道名>` 时，询问"你已有 [日期] 的分析，要更新还是新建一份？"
- **不自动删除**——格局报告是历史记录，用户可以看赛道格局随时间的变化
- **不进入 rubric 循环**——格局分析是一次性 / 定期的战略动作，不是每篇视频都要跑的操作流程
